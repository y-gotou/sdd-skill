# 工程: 実装計画(→ G2)

対象: scale が medium / large のタスク。small は本工程をスキップする(検証方法は票に記載済み・G1 で承認済み)。

## 0. ゲート検証

spec.md の `approvals.spec` に承認日があることを確認する。無ければ停止し、起票工程(01-intake.md)へ戻る。

## 1. plan.md 作成

`references/templates/plan.md` から `docs/tasks/T-NNN_件名/plan.md` を作成する。

- **設計判断**: 採用方式と理由。ファイル名・関数名等の実装詳細はここに書く(spec.md には書かない)。large では検討した代替案と不採用理由も残す。
- **影響範囲**: 変更対象(モジュール・画面・データ・設定・恒久仕様書の節)。
- **作業項目**: 粗い粒度(1項目=1コミット〜半日目安)のチェックリスト。ファイル単位まで細分化しない。
- **検証方法**: `_config.md` の検証系統から選び、「エージェント実施」「実環境・ユーザー実施」に必ず分ける。
- **仕様書反映**: `_config.md` のリリース運用が「実装 PR に同梱」の場合、恒久仕様書の更新を作業項目に含める(G3 では反映済み内容を追認する)。

## 2. G2 承認

- 設計判断・影響範囲・作業項目・検証方法を提示し、承認を求める。
- 承認を得たら spec.md の frontmatter に `approvals.plan: <日付>` と `updated` を記録し、backlog.py を実行する。作業ブランチ上での承認なら main へ同期する(references/03-work.md §5)。
- **G2 承認前に実装へ進まない。**
